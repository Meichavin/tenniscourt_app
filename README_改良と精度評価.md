# ひび割れ計測アプリ 改良内容と精度評価

## ファイル構成

| ファイル | 内容 |
|---|---|
| `tenniscourt_app.py` | Streamlit アプリ（改良版）。**このファイル単体で動く**（解析部分も内蔵） |
| `crack_core.py` | ひび割れ検出の本体（アプリ内蔵部分と同じ内容。評価スクリプト用） |
| `tenniscourt_app_old.py` | 改良前のアプリ（バックアップ） |
| `evaluate_accuracy.py` | 精度評価スクリプト |
| `evaluation/` | 評価結果（CSV・画像） |

起動: `streamlit run tenniscourt_app.py`（Streamlit Cloud には `tenniscourt_app.py` だけ置けば動く。必要なライブラリは旧版と同じ）
※ 解析方法を変更するときは、アプリ内の解析部分と `crack_core.py` の両方を同じように直してください。

## 1. 写真から分かった旧版の問題点

| 問題 | 写真での例 | 旧版で起きていたこと |
|---|---|---|
| 緑の枠ひもが写っている | ほぼ全写真 | 枠ひもを「ひび」として数えていた |
| 解像度が 1280px と 3024px の2種類 | 10_17, 10_31 など | 同じ地面でも解像度で値が最大 39% 変わる |
| 木の影・濡れムラ | 10_06, 10_31(2), 10_13 | 影の境目を拾う／暗い所で誤検出 |
| 地面のザラつき（砂粒・小石） | 全写真 | Otsu 法が「必ず何かをひびにする」ため、砂粒を大量に検出。ひびの無い写真でもひびの多い写真と同程度の値（延長密度 ≒ 23,000〜55,000） |
| 足跡・ブラシ跡 | 10_28, 11_21 | 線状に見える凹凸を拾う |

## 2. 改良内容（`crack_core.py`）

1. **解像度の正規化**：全画像を長辺 1600px にそろえてから解析
2. **計測枠の自動除外**：緑のひも・四隅の白いピン・枠の外側をマスク
3. **照明ムラ補正**：ぼかした背景との明るさの比で判定（影・濡れムラに強い）
4. **線状構造の強調**：ヘッセ行列の「暗い谷線」フィルタ ＋ 16方向の線積分で「長く続く細い線」だけを強調。小石（点）や砂粒（短い）を抑制
5. **雑音基準の閾値**：その場所の地面のザラつきの何倍暗いか、で判定（Otsu 廃止）
6. **形状フィルタ**：短い・広がりの小さい成分、細かいヒゲ（枝）を除去
7. **長さの正しい計測**：斜めのつながりを √2 で数える
8. **速度**：1枚 約 40 秒（初期試作）→ 約 5 秒

アプリ側の追加機能：
- 検出感度（低・標準・高）の切替
- 枠の一辺 [cm] を入れると **cm・cm/m²・mm** で表示
- ファイル名（`10_31(2).jpg`）から **撮影日と地点を自動入力**、**一括登録**タブ
- 履歴の日付を「保存した日時」から「撮影日」に変更
- 旧版の記録と改良版の記録を区別（`algo` 列）。推移グラフは同じ方式どうしのみ表示

## 3. 精度評価

人がなぞった正解データが無いため、次の方法で評価しました（`python evaluate_accuracy.py <画像フォルダ>` で再実行可）。

### A. 合成ひび試験（正解が分かっている人工ひびで検出精度を測る）

ひびのほとんど無い実写真5枚（10_27, 10_27(2), 11_10, 11_10(2), 11_06(2)）に、長さが分かっている人工のひび網を描き込み、検出結果と比較。
ひびの濃さは、実写真で検出されたひびの暗さに合わせて4段階に設定（濃い≒10_21・10_31、普通≒10_19・10_28(2)、薄い≒10_06・10_19 の薄い方、極薄＝地面のザラつきと同程度で目でもほぼ見えない）。
位置の許容誤差は 4px（解析サイズ 1600px 基準、枠1mなら約 2.5mm）。

| 濃さ | 旧版 適合率 | 旧版 再現率 | 旧版 F1 | **改良版 適合率** | **改良版 再現率** | **改良版 F1** | 改良版 延長誤差 |
|---|---|---|---|---|---|---|---|
| 濃い | 0.06 | 0.93 | 0.12 | **0.73** | **0.70** | **0.71** | −13% |
| 普通 | 0.04 | 0.91 | 0.08 | **0.65** | **0.65** | **0.64** | −13% |
| 薄い | 0.05 | 0.90 | 0.09 | **0.61** | **0.50** | **0.53** | −31% |
| 極薄 | 0.03 | 0.82 | 0.06 | 0.34 | 0.19 | 0.23 | −60% |

- 適合率 = 検出した線のうち本当にひびだった割合／再現率 = 本当のひびのうち検出できた割合
- 旧版は再現率こそ高いものの、**検出した線の 95% 以上がひび以外**（総延長が正解の約 20 倍）で、ひびの量を測れていませんでした
- 改良版は F1 が約 **0.1 → 0.6〜0.7** に改善
- 背景別（極薄を除く）の F1：10_27(2) 0.81 / 10_27 0.80 / 11_10 0.78 / 11_10(2) 0.65 / **11_06(2) 0.10**
  → 低い日差しで凹凸の影が強い暗い地面（11_06(2)）は苦手

## 4. 限界と注意点

- **濡れた日・雨上がりの写真はひびが写らない**ため値が小さくなります（10_27, 11_10）。これは解析の誤りではなく写真の問題です。推移を見るときは乾いた日の写真どうしを比べるか、メモ欄に「雨後」と記録してください。
- **日差しの角度で値が変わります**。低い日差し（朝夕）は凹凸の影でひびが濃く見え、足跡なども拾いやすくなります（11_06(2), 11_21）。できるだけ同じ時間帯に撮影するのがおすすめです。
- 細く薄いひび（地面のザラつきと同程度）は半分以上見逃します（合成試験の「極薄」）。
- 合成ひびは実際のひびを完全には再現していないため、上の数値は「目安」です。より正確に評価するには、何枚かの写真で人がひびをなぞった正解画像を作り、`match_score` で比較するのが確実です。
- 旧版で保存した記録（`algo = v1`）と改良版の記録は数値の基準が違うため、直接比較できません。
